## 1. Architecture Review

### A1 · [P1]（置信度 10/10）业务依据缺少必要展示字段

`services/openform/analysis/service.py:160` 当前查询为 `SELECT a.id AS record_id,a.number,s.data,s.receipt,s.created_at`；`service.py:63` 报告题目只有 `id`、`title`、`kind`。`AnalysisView.tsx:108` 直接调用 `JSON.stringify(evidence, null, 2)`。仅更换样式无法可靠得到学生称呼和答案路径。

**采用局部补齐方案 [Layer 1]。** 依据接口保留 `_report`、快照成员与 `records.read` 校验，加入显示称呼、小组（如适用）、题目/答案展示所需元数据。题目、路径、标准与选择项来自该报告关联的发布版本或固定报告内容，不取活动当前草稿。答案取该报告所引用的具体提交，不用学生后来提交替换。姓名缺失时明确显示未提供称呼，不用 UUID 顶替。

课堂结果如需展示未交学生，必须从开课名单快照与真实参与/提交记录取得。现有 `classroom_records` 仅返回最终提交，不能在前端从当前班级名单或已加载的一页答案推算未交者。局部增加受 `records.read` 保护的分页参与状态读取，复用 `Page` 与现有 SQL 关联；不另建名单服务。只需学生称呼、小组、是否名单内、进入/保存状态、是否曾提交及可打开的记录标识。

权衡：比全站业务 API 重写小；需要少量前后端同时修改。替代方案“前端猜测或全部加载记录再关联”会错配旧版本、漏掉分页数据，拒绝采用。不会把学生姓名加入发给模型的快照。

### A2 · [P2]（置信度 10/10）课堂入口未携带课堂上下文

`TeachingView.tsx:176` 链接为 `href="#S01"`；`roster.ts:18–31` 路由未解析课堂码；`StudentPortal.tsx:88` 要求再次填写课堂码。正式设计第 63 行要求学生链接及指引卡。

**采用公开课堂定位码入口 [Layer 1/2]。** 教师获得形如 `/#S01?code=XXXXXXXX` 的完整学生链接、复制动作、本地生成二维码和打印指引卡。只包含课堂定位码；个人进入码、CSRF、会话凭据及学生身份不进入 URL、二维码或指引卡。学生验证个人码之后仍保留目标课堂；临时参与者填写称呼后使用同一目标，服务器决定是否允许进入。

复用当前 hash 路由、课堂码加入接口和认证接口。二维码采用本地打包的 `qrcode` 浏览器能力、锁定依赖并保留许可；不使用在线二维码服务或 CDN。该库支持浏览器使用并采用 MIT 许可，见[项目文档](https://github.com/soldair/node-qrcode)。链接生成依据实际部署 origin，打印使用页面本身，避免新增 PDF 服务。

权衡：保持现有身份模型且不增加后端写入；须处理打印和认证后目标保留。仅增加二维码却仍指向通用入口无效；将课堂码当身份凭据也无效。

### A3 · [P1]（置信度 9/10）学生内容优化不能破坏运行隔离与版本不可变

`ActivityFrame.tsx:24` 使用 `sandbox="allow-scripts"`；`RuntimePlayer.tsx:58–62` 校验回执与尝试；`styles.css:90` iframe 最小高度为 `70vh`。QA 窄屏题目被身份说明与系统状态挤下，底部操作后的错误不在视野内。

**采用紧凑宿主与明确的活动视区 [Layer 1]。** 压缩外层身份区，答题屏以课堂题目和活动视区为主体；依据可用视口设置活动区，在答题状态避免外层与内层同时形成难以操作的滚动区域。图片添加时切换到清楚的上传区域，完成后返回作答。样板内保存、提交、失败反馈放在动作附近并确保可见。对不能保证尺寸的导入内容保留可操作的滚动视区，不裁掉底部按钮。

不增加 `allow-same-origin`，不将不可信 HTML 注入教师 DOM，不把管理会话传入活动页。此轮不新增自动高度桥接协议。`sample.js` 的修改仅进入新草稿及新发布版本，已发布版本不被偷偷重写；需要改旧活动时生成新草稿、重新试做确认和发布，再开新课堂。

## 2. Code Quality Review

### C1 · [P1]（置信度 10/10）两次创建首先失败于 JSON 字符串序列化

线上任务 `dfec4fc2-dc06-4daa-b211-af3fe643bcc1` 与 `e26d0439-7646-4804-9fa8-8e5625a17e23` 均返回 `MODEL_INVALID_OUTPUT`。去掉既有支持的 JSON 代码围栏后，严格 JSON 解析分别在第 50 行第 35 列、第 55 行第 35 列失败：`files.index.html` 字符串中有未转义换行。只读宽松解析仅用于定位问题，未用于产品接收结果；它不能证明后续包校验或真实操作会通过。

源码链为 `ark.complete → model_page → prepare_draft → write_draft`。`authoring/packages.py:31` 为 `json.loads(value)`；`models/ark.py:42–44` 当前请求没有 `response_format`。`jobs/runner.py:150–152` 将生成解析、包校验和诊断引用错误统一映射成“模型输出不符合当前约定或引用了快照外依据”。

**采用供应商 JSON 输出约束与严格接收 [Layer 1]。** 在制作调用明确请求 `response_format={"type":"json_object"}`，提示中保留 JSON 要求并提供经标准序列化的完整页面包范例，包含 HTML 换行和引号的正确转义。先核对实际配置的模型与推理方式是否支持；不擅自更换模型、不在供应商拒绝参数后偷偷退回无约束输出。火山文档提供该模式，但注明推理方式限制与 beta 状态；这是实现依据，尚不是当前环境调用已验证。见[结构化输出文档](https://docs.volcengine.com/docs/ark/structured-output-beta?lang=zh)及[模型列表](https://docs.volcengine.com/docs/ark/model-list?lang=en)。

完整 JSON 之后仍执行现有清单、字段、资源、安全、评分及真实试做门槛；不启用产品级 `strict=False`、不正则拼接截断 JSON、不删除被拒标签来伪造可用草稿。本次不增加自动二次模型修复或新收费调用。若参数不兼容，明确归为服务配置问题；若返回仍无效，保留教学要求与已有活动，让用户继续修改要求或选择样板。

按制作/诊断及解析/兼容/版本冲突分开安全错误映射。后台留错误阶段、规则编号和已授权任务关联；用户看到业务失败与下一步，不看到代码、原输出或供应商费用核对指令。格式成功不冒称题目、保存、提交已通过。

### C2 · [P1]（置信度 8/10）诊断成功状态可能取消随后报告请求

`AnalysisView.tsx:37` 先 `setJob(value)`，第 39 行再用原 `signal` 执行 `openReport`、`loadReports`；第 59–62 行轮询依赖 `job?.status`，清理执行 `controller.abort()`。任务变为成功触发依赖清理时，随后报告读取可被取消，错误又因已 aborted 不显示。线上两个课堂已复现结果缺位；这条主分支取消路径是高可信原因，仍须在对应运行版本核对取消请求，不能冒称已经取得线上网络证明。

**采用分离生命周期方案 [Layer 1]。** 轮询只读任务，报告读取用课堂/组件生命周期管理，终态一次同步报告和历史；选择序号继续防止迟到响应覆盖新选择。报告读取失败显示“报告暂时未能打开”的业务恢复动作，重试读取原报告，不再创建模型任务。切换课堂、账号或空间时取消请求并清除旧报告/依据/复核勾选，不用去掉全部 abort 来掩盖问题。

复核完成后标题和按钮以报告的 `reviewed_at` 为准，不让固定任务成功标签继续声称待复核。无报告、正在生成、读取失败、资料失效和无权限分开呈现。

### C3 · [P1]（置信度 10/10）主页面以处理记录而非业务内容组织

`AuthoringView.tsx:185` 制作任务默认 `open`，第 186 行显示任务 ID 与 tokens；`TeachingView.tsx:141` 先渲染制作器，第 149–159 行才显示题目和试做；`App.tsx:173` 制作仍保留完整业务侧栏。`RuntimePlayer.tsx:142` 显示服务端版本和回执 ID；`ActivityFrame.tsx:23` 显示通信已建立。`TeachingView.tsx:177` 无条件呈现不适用的名单指标。`AnalysisView.tsx:97–108` 将机制说明、用量、快照规则和 JSON 置于正常操作中。

**采用业务结构重排 [Layer 1]。** 制作保留顶栏和活动上下文、收起业务侧栏，左侧要求与题目内容、右侧实际草稿预览/试做。结果首先是参与、已交、未交和题目表现，再看对应学生作答；快速课堂隐藏不适用的名单完成率，未知不改成零。诊断首先是问题、相关学生作答与讲解建议，输入框和业务按钮使用现有规范。必要范围写作“根据截至某时的 X 份作答”，不把 KiB、coverage 或规则原文当正文。

仅抽取重复的题目/答案展示能力：题干、选择项文本、文本答案、数值单位、开放题和图片均按真实元数据展示；遇到未提供单位或标签时不杜撰。模型解释本身是教学业务内容，保留；系统过程解释不作为业务内容。HTML/JSON 编辑仅保留在用户主动选择的文件导入高级操作中，不能成为普通制作与试做的必经入口。

### C4 · [P2]（置信度 10/10）空状态与个人班级使用了错误上下文

`TeachingView.tsx:147` 写着“尚无活动，请选择上方样板”，但样板只在制作页。`RosterView.tsx:73` 仅按 `workspace.is_admin` 选择任课说明，第 90 行个人班级也渲染 `Assignments`。`StudentClassroom.tsx:76` 历史以尝试和回执编号为主；后端 `participants.py:102–103` 已有名称与时间，前端类型未使用时间。

## 4. Performance Review

### P1 · [P2]（置信度 9/10）轮询方案须避免慢请求重叠及历史任务批量读取

`AnalysisView.tsx:60` 用五秒 `setInterval` 发起请求，没有请求在途保护；`AuthoringView.tsx:78–82` 每次轮询批量读取已显示的所有排队/运行任务。重排 UI 时若为了即时结果提高频率，会放大问题。

**采用单个在途请求与终态一次同步 [Layer 1]。** 保留现有五秒量级，用请求完成后再安排下一次的方式或明确在途锁，组件退出取消；终态停止任务轮询，报告详情/历史按需同步。制作只自动跟随当前制作操作，历史分页按需读取。读取错误保留已有内容和普通用户可执行的重试，不让旧页面静默停在已成功状态。

结果和参与状态继续有界分页，不为渲染卡片逐行请求学生资料；依据仅点击时读取单条，元数据同次返回。没有为此发现实际数据库 N+1，也没有容量测量证据，不增设缓存平台、长连接、性能基准或压力测试。React 的 effect 清理与响应竞争处理参照[官方说明](https://react.dev/reference/react/useEffect)。
