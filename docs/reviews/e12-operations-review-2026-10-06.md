本轮发现的关键问题已在同一轮修复：

| 来源 | 问题 | 修复 |
|---|---|---|
| 原生 P1 | 新安装的数据库 secret 为应用 UID/0600，postgres 初始化不能读取 | root/0700 主机目录内数据库 secret 为 0444，在各容器选择性只读挂载中读取；模型/运维凭据仍 0600 |
| 原生 P1 | 备份后恢复写入，再重新加锁升级，可能有已确认资料不在升级前备份 | 升级备份持续保留维护锁及停止状态，直到迁移/核对完成 |
| 主检查 | 并发运维可导致复制期间提前开放写入 | 每个实例名使用主机 flock，拒绝第二个操作 |
| 主检查 | 新备份尝试覆盖上次成功记录 | pending_backup 单独记录，核验成功才更新 backup，失败继续显示上次成功点 |
| 主检查 | 仅比较编译 schema，未核对实际恢复 schema | 快照和恢复锁都比较数据库 alembic_version |
| 主检查 | 服务重启失败可能留在已开放状态 | 安装/备份恢复写入/开放的 readiness 失败重新维护并停止服务 |
| 主检查 | 非 ASCII 运维凭据触发字符串 compare_digest 错误 | 使用字节常量时间比较，错误凭据不再触发此类型错误 |

修复只检查改动行及必要的格式/类型错误，不登记为第二次完整审查或“修复后已收敛认证”。原生报告针对初始快照；主记录 `converged=false`，外部覆盖缺失单独保留。

## 交付边界

- 恢复目标强制全新 Compose 项目、无旧容器/卷，使用备份时同一应用镜像；数据库恢复前不启动业务，失败不删除原实例或历史备份。
- DB dump/文件静止快照、文件 SHA-256 与图片引用核对后加密；实际加密/异机拷贝/恢复结果由 Q5 单次集成 QA 记录，不能由本代码 review 推定成功。
- 恢复生成新实例 ID/代次，暂停旧会话、账号/成员/任教/协作授权、学生个人码/邀请及旧导出任务；保留提交、活动版本、图片和历史归属。模型结果未知保留预留、不自动重试。
- 独立运维操作限主机 sudo 命令；O01 为单独授权的状态/恢复点视图。学校可读最近备份的日期和核验状态，不能查看/执行整实例恢复。
- 学生设备 DNS/证书信任、独立干净物理主机、真实校园离线课堂与 500 人容量尚未验收。本机隔离容器与 loopback HTTP 演练不能替代这些事实。

已完成相关 ruff 与 TypeScript/Python 类型检查；本轮未运行任何自动化测试。源码合并、镜像、部署和 Q5 分开记录。

文件 secret 绑定挂载不支持重映射 uid/gid/mode，依据 [Docker Compose 官方说明](https://docs.docker.com/reference/compose-file/services/#secrets)；Linux 互斥锁依据 [Python fcntl 文档](https://docs.python.org/3/library/fcntl.html#fcntl.flock)。
