# 课堂图片

E07 使用私有文件卷，业务数据库版本为 `0006_assets`。仅接受真实单帧 PNG/JPEG：流式接收单张最多 10 MiB，解码前检查最长边 4096，限制同时解码数，重新编码去除 EXIF/XMP/ICC 等元数据。Pillow 解码接口依据[官方文档](https://pillow.readthedocs.io/en/stable/reference/Image.html)，输出只保留像素和必要格式信息。

活动调用 `requestUpload` 后，可信宿主展示图片选择区域。教师或学生在隔离活动中先保存当前文字，再在宿主选择照片；原图不发给活动 iframe，iframe 只读取该字段的已校验文件标识。图片落盘、文件元信息事务提交及进度保存是三个可区分的状态，只有收到进度回执才显示已附加。最终提交核验所有文件的空间、参与身份、尝试、字段、ready 状态和实际存储；同一作答最多引用 5 张，缺失文件不会获得完整提交回执。

图片存储设置：`OPENFORM_FILE_DIRECTORY` 默认 `.local/files`，容器 `/data/files`；`OPENFORM_WORKSPACE_FILE_QUOTA` 默认每空间 1 GiB，`OPENFORM_MINIMUM_FREE_DISK_BYTES` 默认 256 MiB。空闲磁盘低于该水位或已使用 90% 时阻止新上传并提示管理员；没有可用文件存储时明确返回失败。文件 ID 为服务端随机 UUID，不采用上传文件名作为路径。

已持久化图片不可覆盖；相同入口重试只允许同一规范化内容。数据库提交响应丢失时不删除可能已经提交的字节。保存引用与进度、最终引用与提交在同一数据库事务完成。已接受的最终提交文件保持原引用。受控查看每次校验本人尝试或教师该课堂的 `records.read` 能力，不提供永久公开 URL；已开始发送或已下载的内容无法远程收回。

`file-cleanup` 每小时清理过期一小时上传预留、超过 24 小时无引用文件和过期暂存字节；逐文件遵循 workspace→attempt→asset→usage 的锁序。仍被进度或最终提交引用的文件不回收。显式删除只允许本人未引用文件，记录删除后再清理字节。源记录生命周期、归档与整体备份恢复在 E10/E11/E12 接入。

Compose 增加专用 `files` 卷和一次性 `files-init`，只初始化该卷的业务进程权限。API 与清理进程共享私有卷，运行域不挂载该卷。原 PostgreSQL 卷、共享主机其他应用和网关主域保持各自配置。

按用户要求，本任务不新增或运行自动化测试。一次 `/review` 后随 E04/E05 集成，统一 Q2 主流程 QA；当前源码不代表部署或浏览器 QA 已通过。
