## 用户问题与授权

用户希望参考 QuickForm 重做项目，服务教师与学校，优先课堂场景，要求同时提供教师版和多用户校园版。原项目核心是为自定义互动网页提供数据收集与读取服务。新产品保留开放网页接入，增加从教学想法、生成活动、课堂参与到结果诊断和校内复用的完整流程。

用户逐项确认：D1 B 新建共享核心；D2 A 扩展模式；D3 A 平台内生成修改单页网页；D4 A 学生进入指引卡；D6 A 保存恢复进度、本人历史、授权共享；D7 A 教学诊断和建议。D5 预览布局问题被用户撤下。

用户随后明确“后续都按你的建议选择”，因此 D8 之后按推荐方案自动决定并注明来源。用户还要求聚焦主要功能；不再恢复体验细节逐项提问。本轮仅研究与评审，无代码、部署、采购或对外发送授权。

## Vision

### 10x Check

教师说出教学想法，得到可试做的活动，确认收集内容后发布；学生的答案、进度和实验观察可保存；教师据此找到需要再讲的地方，同事复制活动后用于自己的课堂。相较只给一个数据接口，这条完整路径可能降低真实课堂使用门槛。10x 是愿景检查，不是实测增益，也不承诺两倍投入。

### Platonic Ideal

普通教师无需写代码，也无需开发人员陪同，可以制作并反复使用一节课的活动。教师清楚知道活动在收什么、学生实际交了什么、结论依据是什么；学校的多位教师能够独立开课，又能积累和复用教学资源。

## Accepted Scope

### 1. 活动创建与接入

教师描述目标、题目或材料，生成浏览器单页活动，也可从模板或外部 HTML 开始。生成与修改均进入草稿预览，教师确认才发布固定版本。活动附带可读的数据说明和适用的题目/评价规则。试做收到真实数据才标记数据接入已验证；该标记不代表题目正确或已经完成教学验收。

外部 HTML 支持单页及经检查的静态资源包，辅助接入同一数据协议。无法识别的交互明确标记并提示修改；不假装自动采集全部点击。执行的页面与管理后台隔离，不能取得管理凭据或任意后台权限。

### 2. 发布与课堂参与

活动模板与一次开展实例分开。快速开展不要求建班级；班级活动可关联名单和任课关系。均支持开放、暂停接收和结束，生成学生链接及指引卡。活动实例固定版本；教师修改模板不影响已发布实例。

临时参与者由服务端发放本活动范围的凭据，同一浏览器可恢复已保存进度；没有名单时不能判断谁未参加。清理凭据后不能凭姓名找回记录。需要跨设备或学生级历史时，由教师发放个人进入码，校方已有可验证身份可通过后续适配接入；共享课堂码仅用于定位活动，不是个人身份。撤销/重置个人码需授权，旧凭据同时失效。校内入口清楚标记网络限制。

个人进入码只是访问凭据，关联空间内稳定学生标识；换码和换班不新建该标识，不拆散原历史。学校管理员维护学校名单身份，获授权任课教师为已有名单条目发码，不同教师共用同一学校学生标识但不能因此读取对方课堂。个人空间使用自己的名单标识，不自动与学校身份合并。临时记录不按同名自动归并；首版不提供临时历史认领。正式学生的本人历史只展示当前获准访问的记录，学校可按活动开放反馈范围。

### 3. 持续互动数据服务

保存结构化答案、明确上报的过程事件、可更新进度和最终提交；仅向本人返回个人记录，向活动参与者返回教师明确开放的汇总或筛选内容。个人历史限定在同一空间内经过验证身份关联的记录，不跨学校自动拼接。

进度与提交历史分开，重试不重复计数。并发更新使用版本检测，冲突不静默覆盖；断网暂存不等于已收到，服务端持久化后才确认。完整提交历史不会因继续闯关、修改模板或同事复制活动而改变。

### 4. 教学诊断与建议

首版分析文本、数值和结构化答案：参与完成、题目/环节表现、开放回答归类、可定位的典型记录，以及基于教学目标的建议。提供自定义分析要求，但不自动执行报告中的操作。

人数等统计由规则计算，模型负责归纳解释。无答案标准不生成正确率；未答与答错分开；参与时长不等于掌握程度。报告注明数据时间、活动版本、覆盖范围和遗漏，关键结论能回到原始记录。教师最终复核，不自动生成正式成绩、长期能力标签或下一次已发布活动。模型不可用仍可查看原始数据、统计和导出。

默认统计口径：人数按同一活动实例的参与者标识去重，至少一次有效完成提交才计为完成；网络重试沿用请求标识，不新增尝试。学生主动重新尝试产生新的尝试标识。题目表现按每人最近一次有效完成提交统计，尝试次数单列；正确率分母为该口径下该题有有效作答的人数，未答人数另列。报告标注这个口径和截止时间；没有名单时不输出缺席名单或全班完成率。每份报告固定数据快照，后续新提交不悄悄改变原报告。

### 5. 校园多用户与复用

教师版与校园版共用核心。个人空间归个人，学校空间归学校；加入学校不迁移个人资产。管理员管理成员、班级、任课、额度和系统运行，查看学生回答另需教学授权。教师只管理本人或明确授权协作的活动和班级。

同事复制校内模板时带页面、题目、静态资源和数据约定，不带学生回答、名单、凭据。复制创建独立活动，原模板更新不覆盖其他教师的课堂。首版协作是明确授权后共同维护资源与查看被授权课堂，编辑冲突检测；不做多人同时编辑文档。成员停用撤销访问，学校资源可按授权交接，历史作者关系保留。

校内库闭环：活动拥有者或明确获得发布权的协作者，将一个已验证版本发布到本校资源库；本校活跃教师可按名称、学科/年级标签搜索并复制。发布仅授予发现和复制资源的权利，不授予修改源活动或查看课堂数据的权利。发布者或学校资源管理员可撤回库中资源，撤回不删除已复制活动，也不改变其课堂。需要修复的资源可发布新版本并提示来源已更新，既有副本由拥有者决定是否另行复制。

### 6. 三类首发样板与材料范围

| 样板 | 主要交互 | 可验证的数据与价值 |
|---|---|---|
| 随堂诊断 | 作答、提交、查看允许公布的反馈 | 客观题错误分布，主观题归类，指导再次讲解 |
| 词汇或概念闯关 | 多次尝试、保存进度、退出继续 | 难点环节、尝试与完成，验证持续互动 |
| 实验探究 | 分步骤记录参数观察结论，上传图片证据 | 比较数值与观察，围绕探究问题讨论 |

图片首版支持 PNG/JPEG 上传、授权查看和导出，明确大小与数量限制；自动分析仍以文本、数值为准。文件检查、配额、权限和任务失败可见是交付条件。其他文件及图片理解、音视频识别后置，不能将上传成功描述成分析成功。首次上线默认每文件 10 MiB、每提交 5 张、最多 4096 像素长边，超限拒绝并说明；部署管理员可收紧，客户端和服务端共同校验。

### 7. 部署、模型与迁移

首版交付同一服务的两种部署说明与包：托管服务支持个人及学校空间；校内部署包先支持一套确定的 Linux 容器环境。具体主机资源通过容量测试确定，托管供应商不在需求评审中采购。教师无需安装 Docker 才能使用托管教师版。

校内无公网时已发布活动、提交、进度和基础统计能使用，网页依赖本地提供。内置生成和模型分析依赖已配置且可达的模型服务；没有服务时明确不可用，允许导入活动，不捆绑承诺本地大模型运行。统一模型适配按实际验证列出支持接口；密钥留在服务端，额度由服务端核验和记账。

无公网可用的准入条件是活动通过必要依赖本地化检查及断网试做，部署环境本身也不依赖外部登录或 CDN。外部 HTML 中无法本地提供的必需脚本、字体或远端业务接口要列出，不能将该活动标记为校内离线可用；首版不承诺自动改造任意远端接口。托管可用、校内联网可用和校内离线可用分别验证。

首版任务包支持迁移页面、配置、版本和选择的数据文件。导入先检查包完整性、协议版本、权限和新标识映射，预览内容再提交；失败不留半个可用活动。跨实例重新授权和绑定数据地址，不迁移可直接使用的凭据。QuickForm 仅兼容已验证的样例和协议，不能宣称任意 QFLink 包开箱即用。实时双向同步不在首版。

资源包与含课堂记录的数据包分开。后者要求源空间导出权和目标空间导入权；导入后成为受限历史档案，不自动关联目标学生、并入当前统计或生成可登录身份。首版不提供档案到学生身份的自动合并；经授权教师可查阅档案及原始来源标识，不能凭同名关联。整实例备份恢复走独立的管理员恢复流程，保留同一空间身份及归属；这与跨空间导入不是同一操作。

部署交付必须包含备份责任说明及管理员入口，验证服务重启后已确认数据仍在，并至少将一个备份恢复到干净实例，核对活动版本、身份和授权关系、进度、提交及图片引用。学校部署由校方明确授权的部署运维人员负责备份与恢复，托管由服务运营方负责；空间管理员不因学校管理角色自动获得整实例备份权限。同一人兼任两个角色也需分别授权。未做恢复验证不得宣称可交付。恢复后旧会话和凭据撤销或重新签发，不能恢复已被撤销的访问。

## 产品价值与验证

核心假设：教师愿意因为更容易制作使用、结果更可信而重复采用；学校愿意因为多人协作、资源积累和可维护部署而组织使用。尚无访谈、付费或运行证据，不把这些假设写成市场结论。

首条完整链路选择词汇闯关，从生成/导入、试做、发布、退出恢复、诊断到复制复用；随后补齐测验和实验样板。个人与学校空间及数据隔离先建，不等到教师版完成后才补校园能力。

试点目标：3–5 位教师、至少一名学校管理员、三个活动样本，完成 5–10 次课堂。无开发人员代操作完成一次完整课堂、至少三位教师自愿再次使用、至少两位教师能指出根据结果做出的具体教学调整，作为继续扩展的信号；这些是评审设定的目标，尚未验证。若未达到，先修复制作、接入或分析阻碍，不自动增加新模块。

容量目标：从每班 50 人、10 位教师同时开展共 500 人的试点目标开始；必须覆盖集中提交、进度读取、图片上传、看板和分析争用。目标不等于已支持，测试环境和负载模型由工程评审固定。留有空间隔离和后台任务限流，先用模块化单体，不引入微服务、通用工作流或区域管理系统。

## NOT in scope

1. 完整教务、考试考务、家长端及区域级行政系统：偏离课堂活动主线。
2. 任意服务端程序生成、通用 IDE、任意数据库访问：无法形成受控课堂产品。
3. 同时编辑同一文档、跨部署实时同步：首版用版本、复制及迁移满足复用。
4. 跨学期长期学生画像、自动正式评分和自动发布教学安排：超出本次活动证据。
5. 公共商业模板市场与跨校社交：先验证校内复用。
6. 所有 QuickForm 页面及迁移包完全兼容：只承诺已验收支持清单。
7. 任意多模态材料自动理解：图片先作为证据供教师查阅。
8. 教师电脑独立离线安装包：单独验证安装升级和网络可达后再做。
9. 学校单点登录和复杂组织层级：先用成员、班级、任课及个人进入码。

## 独立文档复核

范围文档经独立子代理复核 2 轮，第一轮 8/10，发现 6 项问题；修复稳定学生身份、资源发布发现、数据迁移归属、多次尝试统计、无公网准入、备份恢复后，第二轮 9/10、PASS，剩余阻断问题 0。此分数只评价范围文档，不证明产品可运行或教学效果。

子代理使用新的上下文，只读范围文档，没有继承对话；它是同一宿主内的独立复核，不宣称跨模型验证。后续检查还需验证未完成参与者不会被报告覆盖率隐藏，以及恢复旧备份不能恢复已撤销的访问。下列约束已将两者落实到计划。

## 时间顺序检查与交付原则

开始开发前必须明确：空间归属、稳定学生标识、临时身份边界、三种数据（进度/事件/最终结果）及统计口径。核心开发先实现一个可回收真实结果的词汇闯关链路，再扩大生成和分析样例；并行完成校园隔离，不能先以单用户绕过权限。

集成阶段最易误判的是网页能运行但数据没有收到、生成修改后旧课堂悄悄变更、模型只看部分记录却输出全班结论。测试阶段必须能重现重复提交、成员撤销、关闭课堂、模型故障和旧备份恢复。所有下述补救按用户自动选择授权采纳，解决已批准功能的成立条件；不增加新的产品方向。

阶段为工作先后顺序，不是小时或周数的工期承诺。人工团队和 AI 辅助的相对投入见任务表；AI 可以加速实现，但不能压缩掉真实课堂观察、校方配合及恢复验收。

## 1. 架构审查

评估结果：3 项主要设计缺口均形成处理方案，尚待工程验证。R1 生成页面与数据约定脱节；R2 个人/学校归属混用；R3 模型和后台工作阻塞学生提交。

建议采用模块化单体 API、独立任务执行进程及共享协议，管理页面与学生活动运行域分离。React/TypeScript、FastAPI、PostgreSQL 是工程候选，依赖版本由工程评审核验，不是本轮已安装选型。数据库是事实来源，队列使用可恢复任务记录；小规模先不引入微服务。文件存储有本地和对象存储适配，保持业务规则一致。

```text
教师/校管 -> 管理页面 -> API [身份 / 空间 / 活动 / 课堂 / 资源 / 迁移]
                          |                    |
学生 -> 隔离活动域 -> 受限数据接口              |-> 文件存储 [受控读取]
                          |                    |
                          +-------> 数据库 <---+
                                      |
                               持久化任务记录
                                      |
                                  worker -> 模型适配器 -> 已配置模型
                                      |
                                报告/生成草稿 -> 教师复核

原参考流程：外部生成网页 -> 通用任务读写 -> 教师查看
本方案增加：生成/导入 -> 版本与数据约定 -> 课堂实例 -> 稳定参与身份
                         |                    |
                         +-> 校内资源复制     +-> 数据快照 -> 教学诊断
```

新增耦合必须保留：活动版本与题目/数据含义、课堂实例与参与授权、报告与数据快照。避免耦合：学生提交不依赖模型在线；资源复制不携带学生数据；模板编辑不更新已发布课堂；统计不依赖模型是否完成。

API 权限按功能面定义：

| 功能面 | 谁能调用 | 可读/可改边界 |
|---|---|---|
| 草稿、生成、发布 | 活动拥有者或相应协作者 | 本空间获授权活动；生成不能直接发布 |
| 快速活动开课、结束 | 活动拥有者或对应授权协作者 | 本人或获授权活动；不要求先建班或任课关系 |
| 班级活动开课、结束 | 该班任课教师或对应授权协作者，且有活动使用权 | 指定班级与课堂；校管身份不自动等于教学权限 |
| 学校学生名单维护 | 学校管理员 | 本学校稳定学生标识、名单与班级关系，不默认读取课堂回答 |
| 班级名单查看及关联活动 | 该班任课教师或明确获授权者 | 仅获授权班级；个人空间由拥有者维护自己的名单 |
| 进度、提交、本人历史 | 有效参与凭据 | 本人和获准活动；服务端确定空间及参与者 |
| 共享结果 | 活跃参与者、按教师开放规则 | 聚合或筛选内容，不提供全班原始读取口 |
| 诊断、导出、课堂档案 | 获授权教师 | 明确活动/档案范围，任务执行和取结果时均复核 |
| 校内库 | 活跃学校教师；发布需发布权 | 发现复制不授予源编辑或学生数据访问 |
| 成员、额度 | 空间管理员 | 本空间成员及配置，不授予整实例备份或学生明细权限 |
| 整实例备份恢复 | 部署运维/独立恢复管理员 | 备份包含受限课堂数据，须受控加密保存、限权读取并审计；托管学校管理员无此默认权限 |

集成失败按 E01–E24 处理。数据库与单机存储是首轮部署单点，靠备份恢复应对，不能宣传高可用。10 倍负载首先检查集中写入、连接池和图片带宽，100 倍需要新容量评审，不预先建设分布式架构。回退保留已确认提交，不能简单回滚整个数据库覆盖新课堂数据。

## 2. 错误处理与恢复登记

下表是拟建功能的错误契约，名称是计划中的错误类别，不是已存在的异常类。所有行都有明确处理、用户状态、日志和测试计划；没有已经执行的恢复或测试。日志只记录操作标识、错误码、空间及计数，不写模型密钥、学生回答全文、进入码或图片内容。

| 编号 / 功能路径 | 错误类别 | 计划恢复动作 | 用户看见 | 验证 |
|---|---|---|---|---|
| E01 模型生成/分析 | ModelTimeout | 限次退避，耗尽保留任务失败，可手动重试 | 超时及重试状态，原活动可用 | Q1/Q5 |
| E02 模型生成/分析 | ModelRateLimited | 尊重重试间隔，检查额度后排队 | 排队或额度不足 | Q1/Q5/Q8 |
| E03 模型返回 | ModelMalformed | 验证结构，一次受限修复后仍错则失败 | 结果格式错误，不能发布/冒充报告 | Q1/Q5 |
| E04 模型返回 | ModelEmpty | 不保存为空成功，允许重试 | 本次未生成内容 | Q1/Q5 |
| E05 模型返回 | ModelRefusal | 停止自动重试，保留输入供教师修改 | 本次请求未完成及可用说明 | Q1/Q5 |
| E06 导入/生成活动 | ContractMismatch | 列明不匹配项，草稿保留 | 数据接入未验证 | Q1/Q2 |
| E07 活动试做 | PageRuntimeFailure | 记录受限错误信息，禁止验证通过 | 页面操作失败，支持修改 | Q1/Q2 |
| E08 发布/草稿编辑 | RevisionConflict | 拒绝覆盖，重新加载并比较 | 有新版本，需确认后再改 | Q1/Q7 |
| E09 登录/参与/操作 | InvalidCredential / PermissionDenied | 重新验证身份；不按姓名兜底授权 | 凭据失效或无权访问 | Q3/Q6 |
| E10 提交/保存 | PayloadInvalid | 返回字段及大小错误，无部分写入 | 需要修改的数据 | Q2/Q4 |
| E11 请求重试 | IdempotencyConflict | 同键同负载返回原回执，同键异负载拒绝 | 已保存或请求冲突 | Q2/Q4 |
| E12 更新进度 | StateConflict | 比较预期版本，拒绝旧写入 | 另一设备已更新，可重载 | Q4 |
| E13 保存/提交 | SessionNotOpen | 保留本地待处理提示，拒绝记为已收 | 活动已暂停/结束，尚未上传 | Q2/Q4 |
| E14 写入/回执 | DatabaseUnavailable / AckLost | 没回执视为未知；以同请求标识查询或重试 | 待确认，不伪报成功 | Q2/Q4/Q8 |
| E15 上传 | UploadRejected | 校验类型、解码、大小数量，隔离拒绝文件 | 原因与限制，文本可保留 | Q2 |
| E16 上传/文件读取 | StorageUnavailable / MissingBlob | 暂存任务可重试；提交含图时等文件就绪 | 图片未就绪/不可用，不伪报完整 | Q2/Q9 |
| E17 模型额度 | QuotaExceeded | 原子预留/结算，拒绝新模型任务 | 额度不足，课堂收数据继续 | Q5/Q8 |
| E18 报告执行 | AnalysisPartial / InvalidEvidence | 保存明确覆盖与缺失，错误引用不输出 | 部分完成或无法形成结论 | Q5 |
| E19 迁移导入 | InvalidPackage / UnsupportedVersion | 先校验后暂存，失败整体撤销并清理 | 包不支持或内容有误 | Q7 |
| E20 复制/导出 | SourceChanged / SourceUnavailable | 固定源版本，生成清单，失败不发布半成品 | 可重试，原资源不受影响 | Q7 |
| E21 备份恢复 | BackupInvalid / RestoreFailed | 校验清单，在新环境恢复，失败不切换 | 恢复失败与上次可用点 | Q9 |
| E22 任务重跑 | JobLeaseLost / DuplicateExecution | 租约和提交令牌控制单次结果；回收超时任务 | 恢复中，不能重复计费/发布 | Q5/Q8 |
| E23 学校成员/交接 | OwnershipConflict | 同事务验证授权及接收人，失败保持原归属 | 未交接及原因 | Q6 |
| E24 统计/查询 | QueryLimit / InvalidFilter | 分页、范围限制，超限改为异步导出 | 缩小范围或等待导出 | Q5/Q8 |

错误流：

```text
请求/任务 -> 参数及权限检查 -> 执行 -> 持久化 -> 成功回执
              |               |         |
              v               v         v
          纠正后再试       可重试故障   回执丢失
                              |         |
                        有界退避/去重 <-+
                              |
                        耗尽 -> 明确失败 + 操作编号
```

不能使用“吞掉所有异常继续成功”的模式；不可预期错误要由顶层错误边界保留关联编号并返回失败，具体业务错误按表处理。第三方调用日志不得包含凭据和学生原始内容。

## 3. 权限与安全审查

评估结果：5 项威胁，其中 3 项高影响；均有计划中的处理，未做安全验证。

| 威胁 | 可能性 / 影响 | 处理与验收 |
|---|---|---|
| 活动 HTML 获取教师会话或带出学生数据 | 中 / 高 | 独立运行域、受限通道和接口、无管理会话；默认限制第三方网络目的地，测试恶意页面 |
| 改 ID 读取别校/别班/别人的记录或图片 | 中 / 高 | 每次服务端归属及授权检查，后台任务同样检查；Q6 全角色负向用例 |
| 进入码、模型密钥、迁移包泄漏 | 中 / 高 | 密钥服务端保管并可轮换，个人码限速可撤销，包不含活凭据；避免日志泄漏 |
| 学生内容诱导模型越权或改统计 | 中 / 中 | 学生数据只作分析材料，模型无管理执行工具；规则统计独立；错误引用校验 |
| 上传/导入解压攻击、超量资源占用 | 中 / 中 | 文件白名单、解码检查、包路径及展开量约束、存储配额；拒绝任意可执行后端 |

输入校验覆盖缺失、空值、错类型、超长、Unicode、嵌套深度；JSON schema 与教学语义分开校验。数据库使用参数化访问；不拼接用户输入执行 shell 或模板。依赖选型需工程阶段锁定版本、检查许可与已知风险，当前没有安装任何新运行依赖。

数据分为公开模板内容、受限学生/课堂记录、管理审计、秘密凭据。模型只接收本次授权范围必需的材料；调用前说明所用模型服务及发送范围。学校设置保留期限、导出和删除权限，托管个人空间也需显示保留规则；这些参数在实例开通时明确，不能宣称未经核验的合规认证。

资料删除和保留到期是显式数据生命周期操作，不等同继续活动覆盖历史。删除后相关分析失效或引用显示已删除，不用旧缓存重现正文；备份按已说明的周期过期。已下载副本不能被平台自动召回。关键授权、导出、删除、资源交接和配置变更记审计。

## 4. 数据流与交互边界审查

评估结果：8 类数据流和 8 组并发关系已定义。规则为方案要求，并非“写了事务”即已经证明成立。

```text
输入 -> 鉴权/字段验证 -> 转换或计算 -> 提交持久化 -> 返回结果
 |          |                |            |            |
缺失/空   错类型/越权     超时/无结果    重复/冲突    过期/部分
```

| 数据流 | 正常路径 | 缺失（nil） | 合法空集合/空结果 | 错误路径 |
|---|---|---|---|---|
| 教学想法 -> 草稿 | 输入 -> 生成 -> 约定 -> 试做 -> 草稿 | 无目标时提示补充 | 无题目只存草稿 | E01–08，不发布 |
| 活动 -> 发布实例 | 选择版本 -> 验证 -> 固定 -> 开放 | 无版本拒绝 | 无名单可快速开展 | E08/09，原实例不变 |
| 身份 -> 活动进入 | 定位活动 -> 取得/验证凭据 -> 参与者 | 无个人凭据按允许的临时路径 | 名单为空不输出缺席 | E09/13，禁止冒认历史 |
| 答案/进度 -> 数据 | 校验 -> 去重/版本比较 -> 入库 -> 回执 | 无必填项拒绝 | 允许未答但标注 | E10–14，未知不算成功 |
| 图片 -> 记录 | 检查 -> 暂存 -> 就绪 -> 绑定提交 | 无图允许纯文本 | 0 张是合法情况 | E15/16，缺图不伪报完整 |
| 数据 -> 报告 | 固定快照 -> 统计 -> 分批归纳 -> 引用 | 无规则不算正确率 | 0 提交显示暂无结果，不调用模型编造 | E17/18/22/24，覆盖可见 |
| 模板/包 -> 新活动 | 查权 -> 固定清单 -> 复制/导入 -> 提交 | 源缺失停止 | 无学生数据是模板默认 | E19/20，失败清理暂存 |
| 成员/备份 -> 归属恢复 | 查权 -> 交接或恢复 -> 核对 -> 开放 | 无接收人/有效备份停止 | 新学校无成员显示邀请入口 | E21/23，旧环境保持 |

并发安排用 A/B 表示两项操作的持久化完成顺序。每个关键等待点都需用测试钩子暂停、运行另一项、再恢复并启动新读取者；禁止只测试一个顺序。

```text
操作 A：读取当前版本 --[await / 暂停]-- 尝试提交 A ---- 新读取 C
操作 B：                 开始 B ------ 提交 B ---------^
共享状态：旧状态 -------------------- 新状态

A -> B 顺序：必须保留 A 已被确认的事实，B 只能执行其被授权的变化。
B -> A 顺序：A 在最终提交前必须复核版本/状态/权限，不能用旧快照越过 B。
```

| A / B 竞争 | A 先完成 | B 先完成 | 需要的机制与断言 |
|---|---|---|---|
| 保存进度 A / 另一设备保存 B | A 更新，B 旧版本被拒 | B 更新，A 被拒 | 版本比较，同一旧版本最多一项成功 |
| 提交 A / 暂停或结束 B | A 已确认保留，B 后拒绝新提交 | A 拒绝且不入库 | 课堂状态与写入有共同事务序列化点 |
| 写入/导出 A / 撤销成员 B | B 后的新请求无权；已交付内容不能收回 | A 最终写入或新下载授权失败 | 权限纪元及成员行锁/等价机制，提交前复核 |
| 分析发起 A / 新提交 B | A 快照不含 B | A 包含快照内 B | 快照边界持久化，报告数量不漂移 |
| 分析落库 A / 删除数据 B | B 使报告失效或清理引用 | A 不得回写已删正文 | 数据集版本及报告发布检查 |
| 发布 A / 修改草稿 B | A 固定旧版本，B 成新草稿 | A 旧修订请求冲突 | 不可变发布物，按修订版本比较 |
| 模型任务 A / 另一模型任务 B | A 预留额度，B按余额判断 | 反向相同 | 原子额度预留与任务键，不超额/双记费 |
| 模板复制 A / 撤回 B | 已完成副本保留 | 新复制拒绝 | 固定来源版本，完成复制前复核发布状态 |

导出、图片与报告下载每次验证授权，不发永久公开地址；已经开始的传输可能包含已发送字节，撤销不承诺收回。外部模型调用前复核权限，已经发送给模型的内容不宣称可撤回；回写与取结果再查权。

交互边界：双击使用同请求标识；关闭页面后服务器任务可查询；过期身份要求重新进入；列表分页固定游标；0 条显示空态，10,000 条使用分页/异步导出；任务 3/10 批失败显示实际覆盖；队列超限拒绝或等待且说明，不能无限接受后长期无反馈。实验小组首版由指定记录者提交组记录，小组名作为活动字段，不扩展为多人同步编辑；人数统计仍以实际参与身份为准，不把一条小组记录当作所有成员已完成。

状态机：

```text
活动草稿：editing -> validating -> verified -> published(不可变)
                    | error          | edit
                    +-> editing <----+         修改已发布版本 -> 新草稿
课堂实例：prepared -> open <-> paused -> ended
                              open -> ended     ended 不原地重开，复用建新实例
进度：unsaved -> sending -> saved(revision+1)
                  | conflict/offline -> pending -> 重试/重载
提交：pending -> accepted(不可变)；拒绝仍未提交；授权删除 -> tombstone
分析：queued -> running -> completed / partial / failed / cancelled
                                      重试 -> 新任务，保留原运行记录
库资源：private -> published(version) -> withdrawn；复制 -> 独立 private
成员：invited -> active -> disabled；交接检查接收者仍 active
文件：staging -> validated -> attached；失败 -> rejected -> 按策略清理
迁移：received -> validated -> staged -> committed；任一失败 -> aborted
恢复：prepared -> verifying -> ready -> activated；失败 -> 保持旧环境
```

无效跳转由服务端状态检查和事务拒绝：未验证草稿不能标记已验证；结束课堂不再接收；失权成员不交接；暂存图片不能伪装已绑定；部分迁移不能公开使用。草稿验证绑定修订标识，修改即失效。

## 7. 性能审查

发现 3 项主要风险：学生页面反复读取全班明细；图片/迁移一次加载进内存；模型任务与课堂写入争抢资源。措施是聚合/增量读取、分页/流式文件处理、后台任务限额及独立执行。

热点索引由工程设计验证，至少涵盖空间+实例+参与者、请求幂等键、当前进度唯一键、任务状态/下次执行时间；查看班级与报告避免逐条关联查询。聚合缓存必须包含空间、实例、版本与数据快照，不能跨空间共享或把过期进度当事实。连接池和worker并行度受部署资源约束，拒绝无限队列。

最慢路径预计是模型生成/分析、带图片的包导出、集中提交；无代码和负载数据，不能诚实给出实测或可靠估计 p99。建议验收门槛：约定试点环境下普通提交确认 p99 ≤2秒、课中看板数据新鲜度 ≤5秒；图片上传独立测量，生成分析展示排队进度不承诺固定模型时延。门槛须在工程评审中绑定环境及负载，否则不算承诺达成。记录内存峰值、数据库连接占用和队列最大等待，以实测决定容量与限额。

## 8. 可观测性审查

发现 2 项缺口：无法解释“学生说交了但教师没看到”，以及无法发现模型报告只覆盖部分数据。建立从页面请求标识、服务端回执、活动版本到任务/报告的关联链，保留实际覆盖计数。

指标包括：提交确认失败率和待确认数、重复去重数、进度冲突、活动试做成功率、模型队列年龄/失败/费用、报告覆盖、授权拒绝、存储配额、备份最近成功及恢复演练日期。课堂教师看到自己活动的接收与失败状态，系统运维看服务级指标，不默认开放学生原文。

学生数据丢失迹象、连续提交失败、存储接近容量、长队列和备份失败应触发可定位的运行告警。故障手册分别指导：查询回执、恢复worker、限制模型并发、恢复文件、撤销泄漏凭据及执行备份恢复。告警阈值按试点环境配置，当前没有告警系统已经运行的证据。

## 9. 部署与回退审查

发现 3 项风险：schema/活动协议不兼容、恢复旧备份带回失效权限、未本地化网页却承诺离线。采用版本协议检查、默认关闭恢复环境访问、离线活动准入与演练。

```text
测试环境验证 -> 备份并核对 -> 兼容性迁移 -> 部署API/worker/静态文件
       -> 管理/学生探针 -> 小范围课堂 -> 核对回执及指标 -> 扩大使用

上线发现问题 -> 暂停新生成/新开课（已有可用课堂优先保留）
       -> 旧版本是否兼容当前schema及协议？
          是 -> 回退应用/worker -> 冒烟及对账
          否 -> 暂停受影响写入 -> 保留新增数据 -> 修复前滚
灾难恢复 -> 新环境恢复备份 -> 校验记录和文件 -> 重新确认当前授权 -> 切换
```

优先使用新增兼容字段与双版本读取的迁移方式，先迁移再部署；删除旧字段另一次发布。升级窗口的所有写入都必须符合 E14 回执语义；没有零停机证据不宣传零停机升级。生成和分析可独立关闭；收集服务不受模型开关影响。

旧备份可能早于成员停用，因此恢复环境初始只允许独立的恢复管理员进入管理流程，所有教师/参与会话、进入码及恢复出的成员授权暂停。根据当前学校授权重新启用成员并签发新凭据后才开放；不能仅恢复历史授权快照就自动放行。回滚不从备份覆盖当日新记录，灾难恢复必须显示恢复时间点及未覆盖时段，不能隐瞒备份后的潜在数据缺口。

交付前在与目标配置一致的环境完成安装、升级、恢复。上线前5分钟探针验证创建试用实例、保存/读取、提交去重、图片授权及模型失败降级；首小时观察真实请求确认率、负载和队列。运维负责人和实际主机、域名、模型地址属于执行时配置，本次不创建云资源、不外发信息。

## 10. 长期方向审查

总体可逆性 4/5：模块化单体、协议版本和可迁移资源有助换实现；最难改变的是空间归属、身份与统计口径，因此先固定这些语义。债务项目 3 项，与 TODOS.md 一致：独立教师安装、学校SSO、多模态辅助分析。没有把缺失权限或数据可靠性当作可后置债务。
