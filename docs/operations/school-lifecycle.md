# 校园资产与资料生命周期

E10b（2026-10-06）提供服务端校园资产交接、空间配置、运行汇总和课堂资料删除。三端管理页面在 E08 接入，真实集成验收归入 Q4；不能将这些接口的实现描述为已经通过校园现场验收。

- 学校管理员只读取资产名称、当前归属、原作者和修订号等管理信息，不因此获得学生答案。交接逐个指定本校有效教师并确认撤销旧授权；班级课堂的接收者须有当前任课权限。同一事务重新核验归属、修订号和接收者。个人空间不能被学校交接。
- 交接保留活动草稿及固定发布版本，`creator_id` 保留初始归属作者，`ownership_transfers` 保留双方、操作者和时间。旧对象授权全部撤销；新归属教师可重新明确授权。已发布校内资源的管理归属随活动交接，固定资源版本保留历史发布者；已结束课堂及教学资源均不因交接重新开课或复制学生身份。
- 停用校园成员或调整其角色，立即使原会话在该空间失效，重新启用也不能复活原校园会话；需要重新登录。停用或撤销教师角色同时撤销该校旧对象协作授权；保留资产供管理员交接，不删除其个人空间，原会话访问个人及其他学校不受影响。重新启用不会自动恢复已撤销的对象授权。
- 空间配置允许管理员设置资料保留天数、模型累计令牌额度、图片容量，以及分别暂停生成和诊断。学校额度不能超过实例配置；降低额度不抹去已有使用量。关停模型阻止新任务及尚未调用的排队任务，已发出的调用按原任务结算；学生提交不依赖这些开关。
- 默认资料保留 **365 天，从课堂结束起算**，实例可用 `OPENFORM_RECORD_RETENTION_DAYS` 设置，新配置可为 1–3650 天。既有结束课堂以迁移时间作为起点，避免推测历史结束时间导致提前清除。所有空间成员可读取有效保留规则；个人空间拥有者也可调整自己的配置。缩短期限会使已到期课堂进入下一次清理。
- 教师需具备课堂 `records.delete` 能力，先结束课堂，再提供当前资料代次并明确确认删除。校管没有默认删除任意课堂资料的权利。提交删除事务立即提高资料代次、关闭所有原进度/回执/图片/报告/共享读取；相关未调用任务取消并释放预留额度，已调用任务保留费用未知状态；旧 worker 代次不能回写结果。
- 后台清理与图片清理共用现有清理进程，每小时运行。先提交失效标记，后清理提交正文、进度、事件、快照、模型原输出和课堂姓名快照；图片先去引用并扣减用量，再由既有图片清理移除磁盘文件。单课堂清理失败保留不可读标记，可再次执行。保留课堂、尝试标识和审计元数据用于解释删除状态，不提供原答案访问。
- 已发送字节、教师已下载副本及已有备份不能远程召回；备份保留与恢复属于 E12 独立实例运维，不向校管显示虚构的成功备份日期。

接口：`GET/PATCH /api/workspaces/{id}/policy`、管理员 `GET .../status`、管理员 `GET .../assets`、`POST .../assets/{objectId}/transfer`、教师 `DELETE .../classrooms/{classroomId}/records`。全部复用会话、Origin/CSRF、空间事务及 RLS。

运行状态只汇总任务状态、累计已结算/预留令牌、图片字节和待清理数量，不包含密钥、学生正文或模型输入。额度是累计令牌/容量上限，不表示货币预算或自动按月重置。外部模型费用未知不会被伪装为零。

按用户要求不新增或运行自动化测试。源码只做一次 `/review`，适用静态检查由 PR CI 执行；界面、交接与删除的真实集成结果在 Q4 单次 `/qa` 中记录。
