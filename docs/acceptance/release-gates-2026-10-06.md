## 现场需要留下的最少记录

先由学校部署负责人确认应用域与运行域在全部参与设备上能解析并正常校验证书，以及模型/课堂收集的网络边界。再由教师在已确认规模的一节课中完成“进入 → 保存 → 提交回执 → 查看结果”，发现故障记录操作与时间，不复制学生原始答案到 Git。

后续课堂证据只记录以下必要信息，私有材料由学校留存，仓库最多保存匿名汇总及受控引用：

| 字段 | 填写方式 |
|---|---|
| 日期、部署版本、活动类型 | 实际值，未知标为未知 |
| 匿名班级、实际参与数与设备/网络 | 不收集真实学生姓名或个人码 |
| 是否收到持久化回执、教师能否查看 | 记录实际异常数和未确认数，不以界面点击次数代替 |
| 模型建议是否由教师复核 | 记录覆盖范围与不适用情况 |
| 课堂是否完成、遇到问题及处理 | 一个可核对的时间/描述及负责人 |

收齐原定 3–5 位教师、1 位校管和 5–10 节课的事实后再判定真实课堂门槛；无需为了填表重复已经通过的开发 QA。容量事实与现场事实分别确认，未验证的项目继续保留未验证。

## 放行规则

QA 合成演示可以继续；真实学生试用应先确认学校部署、设备和信息使用安排。正式校园发布要补齐相应现场记录并处理阻断问题。E13 的现场验收保持开放，不能因为源码任务和 PR 合并而自动关闭。
