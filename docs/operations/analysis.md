# 课堂快照诊断

教师在课堂结果下创建标准诊断或填写自定义要求。服务端分别核验 `records.read` 和 `analysis.create`；学校管理职责不自动取得个体答案。创建、worker 调用前、结果写入、报告读取和教师复核分别检查权限。

快照在空间/课堂锁内固定发布版本、截止时间、确定性统计和每个参与身份最近一次有效最终提交。模型最多读取 200 份 / 128 KiB 去除身份标识的答案，超过 16 KiB 的单份答案整份遗漏。图片不送入模型，过程事件不在本次诊断输入中。报告注明纳入/总完成/遗漏及上述限制。学生文本中自行填写的个人信息仍可能存在，创建前提示教师确认适合发给已配置供应商。

统计和实际原始提交独立于模型。模型归纳与建议必须携带快照中存在的记录 ID 与题目 ID，引用不存在则拒绝发布，保留原输出与已知用量。平台验证引用存在，不自动验证解释是否合理；教师可打开对应持久化原始记录和回执逐项核对，再记录复核。报告不自动生成成绩、长期能力标签或下一次活动。

报告固定后新提交不覆盖原报告。共享需要已复核报告和课堂管理权，只发布教师单独填写并确认的 2000 字以内摘要，参与身份另核验当前课堂资格与实际参与。完整模型报告、个体原始依据和答案标准不随摘要共享；摘要可撤回。

诊断与生成共用模型额度、持久化任务、受限调度、租约代次和调用未知处理。调用超时/worker 中断后不自动重复扣费，原操作键和原要求可恢复；明确拒绝允许调整。课程统计、续做和提交不依赖模型在线。

源码中已有资料 epoch 与快照失效检查；实际删除、保留到期以及同步清除快照/报告/任务原文在紧接的 E10b 生命周期任务落地，不把该后续操作描述为本 PR 已验收。真实模型、浏览器报告依据、复核与共享在 Q3 统一做一次课堂主流程 QA；语义模型效果评估和全量并发对抗未运行。
