# E03 账号与空间入口

本页对应 E03 第一批：账号、会话、个人/校园成员、邀请和工作台入口。班级、任课、稳定学生、个人码和具体活动/课堂协作权限仍在 E03 后续批次，不登记为已完成。活动页面明确显示尚在开发，不加载原型合成数据冒充业务。

## 账号与校园开通

教师从应用创建本地账号，登录名使用字母、数字、点、短横线或下划线；不依赖邮箱或 SSO。密码至少 12 个字符，使用 pwdlib 的 Argon2id。注册自动建立个人空间，其拥有者可以管理自己的空间。

学校由独立部署运维使用迁移角色开通，普通教师和学校管理员均没有创建任意学校的 API。首位管理员使用绑定登录名、一次性、7 天有效的专用邀请；初始管理身份不自动取得教学职责。

```sh
OPENFORM_DATABASE_URL=postgresql+psycopg://openform_migrate@127.0.0.1:15432/openform OPENFORM_DATABASE_PASSWORD_FILE=/absolute/private/database-migrate.txt uv run python -m openform.manage activate-school --name '学校名称' --admin-login existing-login --invite-file /absolute/private/first-admin.invite
```

邀请文件以 0600 新建，拒绝覆盖已有文件；完整邀请不写控制台或数据库。部署人员将受限文件中的邀请交给指定成员，成员登录后从 `/#G01?invite=邀请值` 核对学校和职责，再接受。使用 fragment 避免把凭据放进 HTTP 请求路径日志。校园邀请由管理员在成员页生成，完整链接只在生成后显示一次；列表可查看状态与撤销。

若命令在 COMMIT 前失败且未完整保存凭据，事务回滚并清理空文件。若凭据已 fsync、提交回执丢失，保留邀请文件，结果视为未知；先由指定账号在应用核验该邀请是否有效，不立即新建另一学校。核验有效可继续接受；无效则由部署运维检查对应学校/邀请的实际数据库状态，再决定恢复或重新开通。不要删除唯一邀请文件来“清理失败”。

## 会话与隔离

账号会话仅保存 256 位随机凭据的 SHA-256 摘要，有效期 12 小时；cookie 为 host-only、HttpOnly、SameSite=Lax，QA/部署环境启用 Secure。写操作同时验证精确 Origin 和绑定当前会话的 CSRF；开发 HTTP 仅在 development 模式使用。退出会撤销服务器会话。

每次请求复核账号、会话、空间和成员的当前有效性，成员角色修改立即影响后续访问。成员启停与角色调整携带读取时的授权代次，旧页面遇到版本冲突会刷新，不能把已撤销的角色重新写回。停用学校成员不撤销其独立个人空间；不能停用或降级最后一位有效学校管理员。成员按固定标识游标分页，每页 50 位，支持姓名/登录名搜索。

账号、会话和限速桶属于全局认证数据。空间、成员和邀请为租户业务表，开启 PostgreSQL RLS；仅在事务内设置账号与空间上下文，空上下文拒绝租户读取。业务数据库角色不拥有 schema、不是超级用户且没有 BYPASSRLS。两个受限 SECURITY DEFINER 函数只定位有效邀请的空间、或读取并锁定实例状态，不开放泛化 SQL 或写入。未知/缺失实例状态按不可用处理。

登录限速按登录名和请求地址；昂贵密码计算最多同时 4 个。邀请核验和接受有限速；身份请求 JSON 上限 16 KiB。日志与错误不包含密码、完整邀请、会话凭据或学生原始内容。

## 本批验证边界

使用专用 PostgreSQL 18 与合成账号，检查空上下文、连接池换空间、越权成员操作、一次性/过期/撤销邀请、最后管理员、会话代次和恢复锁定。外部认证依赖没有使用，不能将模拟角色当正式用户。

真实用户页面和跨角色集成 QA 在 E03 的班级/学生身份批次接入后集中执行，本页不登记其已经通过。CI 仅在 PR 上运行相关检查，合并 main 不重复测试/构建。
