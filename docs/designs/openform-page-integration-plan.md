# OpenForm 页面整合方案

本文件是[页面与主流程方案](openform-page-plan.md)的补充，由本轮 `/plan-design-review` 直接完善。沿用[正式需求](openform-classroom-platform.md)、[DESIGN.md](../../DESIGN.md)和[VI](../brand/visual-identity.md)，保留 22 个业务页面及独立运维 O01。主要结果是明确每页怎样进入、操作后去哪里、哪些变化必须在其他页面出现。

**结论：页面够用，下一步应把它们接成能完成课堂任务的产品原型。** 不新增门户、大屏或通知中心。当前 23 个 HTML 是单页设计与局部连通演示；本轮完成整合规格，尚未修改它们的实现。学生、教师和管理数据均为合成示例，不能用于实际教学。

既有设计位于 `/Users/sjs/.gstack/projects/openform/designs/<ID>-20261004/`，[页面总览](http://127.0.0.1:8771/openform-html-assets-20261004/index.html)。其历史检查记录为 69 张响应截图、78 项页内交互、14 项跨页检查；本轮只核查证据与源码，不把历史数量写成本轮重跑结果。这些局部检查不能证明完整的多活动、多课堂、多角色流程。

完整目标：不借助页面选择器，教师能制作/复用一份活动并开展，学生能进入/提交，教师能找到同一份提交并复核；校管能配置名单和任课，教师收到对应变化；返回、刷新、失效和换空间时不串对象、不丢已确认结果。

## 3. 三个业务入口和一个独立运维入口

```text
工作台入口 G01（已有账号 / 创建个人账号 / 接受学校邀请）
  └─ 获准空间 + 工作区域
     ├─ 教学 → T01 我的活动（默认）
     │  ├─ T02 活动 → T03 制作 / 试做 → P02 开展 → T06 课堂
     │  ├─ T05 我的课堂 → T06 → T07 固定报告
     │  ├─ T08 我的班级 → T09（教学视图）
     │  └─ T12 资料迁移与档案
     ├─ 校内资源 → T10 → T11 → 独立草稿 T03
     ├─ 校园管理 → C01（默认） / C02 / C03 / C06
     │  ├─ 资源管理 → T10/T11（管理模式）
     │  └─ 班级管理 → T09（管理视图）
     └─ 当前空间设置 → G02

学生活动入口（链接 / 二维码 / 课堂码）→ S01 → S02 → S03
  └─ 本人记录 S04 ↔ 对应课堂的进度/回执；已开放内容 → S05

独立运维入口 → 单独核验运维身份 → O01
```

- 教师首页仍是 T01，纯校管首页仍是 C01；兼任者切换已获授权的工作区域，不通过“选择角色”获得权限。个人空间不呈现校内资源和校园管理。
- 工作台 Logo 返回当前空间、当前区域首页；G01 Logo 留在工作台登录入口。学生 Logo 留在当前参与入口，作答中离开先处理未确认内容；不通向教师后台。
- G02/T09/T10/T11 依实际入口显示当前区域导航与面包屑，内容权限另核验。例如 C02 → T09 管理视图返回 C02；T08 → T09 返回 T08。`mode=admin` 只是视图请求，不能赋权。
- O01 不显示教学/校园模块，不出现在一般校管菜单。它不是“第四个业务角色”按钮。
- 原 23 页总览保留作设计目录。整合原型另设**演示入口**，可选教师/校管/学生测试身份、重置合成数据；显式标注演示。正常页面不常驻底部页面/状态选择器，不能用它补救缺失的业务入口。
- 不增加业务首页：全局只显示空间、当前区域和页面；具体对象页面首屏优先“对象名、当前状态、下一动作”，其后才是更多信息。

## 4. 全部页面的进入、定位与完成去向

这里约定可观察的导航契约，不锁定前端框架。对象标识可放在路径或查询参数；工程实现固定一种形式。示例 `?space=school-qh&activity=a-vocab` 仅说明定位结构，不是授权凭据；个人码、会话令牌不放到 URL。

## 5. 必须连通的主要功能

### 5.1 制作、试做、开展是一条链

1. P01 的教学想法、三类样板、HTML 导入都创建本空间的独立草稿；返回 T01 能找到。未给名称用可修改的“未命名活动”，不能默认为同一词汇活动。
2. T03 编辑保存后，T01/T02 名称、修订和验证状态同步；试做结果与活动、修订、试做会话绑定。修改后旧验证不再放行当前稿。
3. “打开学生视角”也必须属于当前草稿的试做会话，并显示“试做”；不能复用学生正式身份、记录、共享开关或回执。回制作器仍是原草稿/修订。
4. T02 选已固定验证版本，T03 选当前已验证修订，T09 预选本班：三者复用同一 P02，保留快速/班级、参与范围、反馈范围、立即或稍后开放选项。
5. 确认成功创建新课堂标识；T06 显示刚才确认的名称、版本、班级/快速方式和状态。T05、T02 历次课堂、T09 获权课堂、T01 继续入口能找到它。全新课堂不能凭空带入 38/34 等历史数字。
6. 重试查询原创建结果；“再次开展”才创建另一次。旧课堂的版本、参与和报告保持原值。结束不可直接重开。

### 5.2 学生参与必须在教师端对得上

每份进度/尝试至少关联**空间、课堂、参与者、尝试**，不能仅按姓名或活动样板保存。回执还要指向其固定版本与明确尝试。浏览器 URL 只定位，访问权由实际身份核验。

P03 的链接、二维码、课堂码都定位同一次课堂，不含个人码/管理地址。班级模式个人码验证稳定身份并核验范围；快速模式临时参与仅当前课堂。T09/C03 发放的示例码必须在 S01 按同一记录验证，禁止两处手写不同合法码表。

S02 已保存 → T06 显示进行中，不能计完成；持久化最终回执 → S03、S04、T06 指向同一提交；重试不增加人数/尝试；主动新尝试保留旧回执。教师暂停/恢复/结束后，学生的可操作状态随该课堂更新，其他课堂不变。

整合原型验收至少打开同一浏览器的两个独立标签页，分别扮演教师和学生，共享同一组合成课堂状态，角色会话分别保存。切换另一课堂/空间不能串记录。具体本地状态共享机制留给工程实现；不得以同标签页继承状态充当多用户验证。真实跨设备、权限和持久化由后端阶段另验收。

### 5.3 校园管理改变教师实际可用范围

建立“有效成员 → 班级 → 学生名单 → 任课关系 → 教师可用班级 → 学生参与”的关联。C02 创建或改班、C03 调整名单、C02 指定任课后，T08/T09 和 P02 读取同一结果。是否有任课、是否有名单分别提示，不用一个“已配置”掩盖缺项。

## 6. 跨页状态和恢复矩阵

主方案第 9 节逐页五态继续有效，下表补的是跳转/两个角色之间的状态。所有成功文案须匹配当前阶段的真实依据：原型只称演示确认，正式应用依服务端确认。

| 功能 | 加载/等待 | 空态 | 错误与恢复 | 成功 | 部分/受限 |
|---|---|---|---|---|---|
| 登录返回 | 保留本站目标，显示核验中 | 无原目标去获准首页 | 失败留非秘密输入；无效邀请不接受 | 回原对象及标签 | 已登录但对象无权，给可用空间入口 |
| 换空间/区域 | 原内容退场，显示目标空间读取中 | 新空间无内容给合适创建动作 | 保留来源信息与重试，不带旧名单 | 新导航、对象列表来自新空间 | 教学角色无管理入口；退出管理不损失教学角色 |
| 对象深链接 | 页面框架标识正在读取 | 真正不存在显示对象不可用 | 读取失败可重试；不加载默认示例 | 名称、面包屑、版本均对应标识 | 不泄露无权限对象标题/记录；返回获准列表 |
| 草稿/试做/开展 | 草稿可读，显示当前操作 | 新草稿空内容引导三种制作方式 | 保存失败留输入；创建结果未知查原操作 | 新课堂可找回，入口一致 | 部分试做缺项不可开展；旧已验证版仍可按规则选择 |
| 学生保存/提交 | 就近说明老师是否已确认 | 未作答不计错误/完成 | 断网暂存；冲突不覆盖；回执未知先查原尝试 | 回执、教师记录、本人记录一致 | 图片未就绪不报完整提交；暂停/结束不补造成功 |
| 名单/任课/发码 | 保存中保留旧已确认值 | 名单/任课空态分别给入口 | 失败回原对象；重复码/失效成员明确 | T08/T09/P02/S01 读到同一结果 | 部分名单行校验失败按预检规则处理，不混成全量成功 |
| 诊断/共享 | 旧报告可读，新任务等待 | 无记录给回课堂入口；无共享内容说明 | 模型失败保留规则统计；失效依据标明 | 新报告可找回；发布版本预览与学生读取一致 | 未覆盖/未完成分别显示；撤回共享不影响本人回执 |
| 复制/迁移/交接 | 可离开并从对象找回任务 | 没有合适对象说明原因 | 失败保持原归属/已存在对象 | 列表/详情同步，指向明确产物 | 只读、无发布权、无档案权限不假装完成 |

离开规则：无未保存输入直接走；有输入给“保存后离开 / 放弃本次修改 / 继续编辑”，保存失败留原页。正在创建课堂/导入/生成报告时退出不会取消已受理任务，再进入查其结果；用户若要取消，必须显示实际可否取消。学生明确退出时说明未确认内容尚未交，并清除该身份在共享设备上的展示及本地未确认材料；仅保留服务端已确认记录供再次验证后查询，不清除其他角色已确认的演示业务数据。

列表的返回恢复空间、筛选、页码和原条目位置；对象已消失时停最近可用位置并说明原因。浏览器前进/后退按同样规则处理。深链接缺少来源时回所属列表。登录或刷新不能把“最后一份回执”替换为当前请求的成功结果。

## 7. 用户旅程故事板

以下情绪是待试点验证的假设。5 秒能识别对象和下一步，5 分钟能完成核心操作，长期能找回版本、来源和自己已经确认的结果。

| 步骤 | 用户做什么 | 可能感受 | 方案如何连续支持 |
|---|---|---|---|
| 1 | 教师登录后进自己的空间 | 怕走错学校或账号 | G01 返回获准目标；顶栏固定空间/区域 |

| 3 | 试做后再改题 | 担心学生交了收不到 | 试做独立且绑定修订，修改后重新检查 |
| 4 | 为本班或快速开展 | 课前着急，不愿重复填 | P02 继承正确活动/班级，T06 是刚创建的课堂 |

## 8. 设计系统、响应与可访问性

不改视觉方向。工作台继续 `{components.topbar}` 60px、`{components.sidebar}` 240/64px、`{colors.canvas}` #F5F5F5、`{colors.primary-strong}` #5B4BCB；Logo 用正式 SVG。导航选中与权限无关，选中态不能让人以为获得授权。教师桌面 14px 正文/13px 表格，学生 16px 正文/22px 题干，采用已确认中文字体栈；不套营销页字体或渐变规范。

新增的“上下文提示、返回来源、任务结果”使用现有面包屑、状态条、列表行、dialog/drawer，不增加一套首页卡片。导航和标题依对象数据输出，同一对象不在各页另写一套名字。

| 场景 | 桌面 ≥1280 | 平板 768–1279 | 手机 320–767 |
|---|---|---|---|
| 工作台跨区/空间 | 既定顶部区域 + 240px 侧栏 | 64px 图标侧栏，标签可由键盘/触控发现 | 展开导航中仍有全部获准模块与空间入口，选完关闭，当前空间始终可见 |
| T03 制作→试做→开展 | 沿用双工作区与标签 | 编辑/预览切换保留修订 | 单工作区域，试做和检查可切换；开展确认不被软键盘遮住 |
| 列表→详情→返回 | 恢复筛选及行位置 | 仍保留当前筛选 | 横滚限表格容器；名称和主动作可达，不靠悬停 |
| T07→依据→返回 | 抽屉保留原结论 | 抽屉或合适宽度弹层 | 全屏证据，返回到原结论；不要跳报告顶部 |
| S01→S02→S03 | 单列最大 720px | 同一参与布局 | 输入/错误/主动作可滚入可见区，48px 主按钮和56px选项；回执可完整读到 |

跨页后将焦点放到新页主标题，读屏播报页面名与必要状态；返回列表恢复来源行/按钮焦点，若已不存在则到列表标题。同页标签切换、弹层焦点锁定、Escape 与关闭返回沿用主方案。手机导航关闭返回触发按钮；新页打开重置导航展开状态。提交、离开确认不叠多个弹窗。

正文对比目标 4.5:1；状态有文字；触控目标至少44px，桌面32px控件在触控条件下扩展。200%缩放、键盘、减少动态效果与实际辅助技术检查是整合后的必做验收，不从截图推定通过。
